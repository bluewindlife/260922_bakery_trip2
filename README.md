## 駐車方針（WRX S4）

- 予算は1店舗あたり最大1,000円、店舗まで徒歩5分以内。
- Samouraïは店舗横・松林寺の店舗専用区画（計6台）、カフェタナカは店舗駐車場25台を使用。
- naは「タイムズ千種内山」（77台、30分200円、24時間最大800円、徒歩約3〜4分）。公式ページのリアルタイム満空表示へ直リンク。
- TETRACONTAは「タイムズ大杉1丁目」（6台、60分220円、24時間最大660円、徒歩約4〜5分）。公式ページのリアルタイム満空表示へ直リンク。
- WRX S4の車幅と低い車高を考慮し、最低地上高15cm以上が条件のロック板式駐車場と、全幅1.85m上限で狭い予約駐車場は採用しない。
- HARU、NILS、pêcheは専用・会場駐車場所を使用し、満車時に近隣施設へ無断駐車しない。

## サイト設計

- スマートフォン最優先
- 写真は各店舗カード内に配置し、独立した重複プレビューを設けない
- 本命店は複数写真、追加候補は原則1店1枚
- 「9/22確認済み」「通常営業」「公式定番」「個別在庫未確認」を分離
- 商品名を特定できない写真は「店頭イメージ」と明記
- 外部画像が失敗した場合は該当`figure`だけを削除し、空の`gallery`も削除
- 同じ画像URLが重複した場合はJavaScriptで後発の`figure`を削除
- 訪問チェックと出発前チェックをブラウザに保存
- 訪問先ごとに料金・台数・徒歩時間・WRX S4の車両条件・満車時の判断を表示
- リアルタイム満空を提供する駐車場は公式ページへ直接リンク
- sticky進捗は本文の流れ内に置き、画面を覆わない高さに制限

画像要素はHTMLだけで生成し、`script.js`は画像を追加しません。過去の「HTMLとJavaScriptの二重生成」を避けるための方針です。

## ファイル

- `index.html` — 旅程・店舗カード・写真・出典
- `style.css` — モバイルファーストのレイアウト
- `script.js` — 進捗保存、画像失敗時の非表示、重複防止
- `.github/workflows/pages.yml` — GitHub ActionsによるPages公開

CSS/JavaScriptの読み込みには日付ベースのキャッシュバスターを付与しています。

## 公開

`main`へのpushでGitHub Actionsが実行され、GitHub Pagesへ公開されます。PagesのSourceは **GitHub Actions** を前提とします。

```text
main push
  → actions/checkout
  → actions/configure-pages
  → actions/upload-pages-artifact
  → actions/deploy-pages
```

## 検証項目

- HTML/CSS/JavaScriptの構文
- `index.html`から参照するローカルファイルの存在
- 同一画像URLの重複
- 外部リンクのHTTPS化と外部タブ属性
- 390px相当での横スクロール、カード崩れ、文字サイズ
- 外部画像の読込失敗時に巨大な空白を残さないこと
- 公開後Pagesでの最新版・画像・リンク・sticky表示
- GitHub Actions最新Runの成功
